# 0003. 함수 호출은 `run()` 안의 프레임 전환

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
어떤 Lox 입력에도 크래시 없이 진단 메시지와 규약된 종료 코드로 끝나야 한다. 깊은 재귀도 C 스택 오버플로로 죽으면 안 된다.

## 결정
함수 호출은 `CallFrame` 배열에 프레임을 쌓고 `run()` 루프 안에서 전환한다. 깊이는 `FRAMES_MAX`(64)로 제한하고, 넘으면 `Stack overflow.` 런타임 에러(종료 코드 70)와 스택 트레이스를 낸다.
슬롯 0은 예약해 메서드와 `init`에서 `this`가 놓이게 한다.

## 대안
- C 재귀로 `run()` 재호출: C 스택 깊이를 제어할 수 없다.
- 슬롯 0 없이 인자부터: 메서드에서 `this`를 둘 자리를 따로 만들어야 한다.

## 결과
- 장점: 호출 비용이 작고, 콜 깊이를 직접 제어한다.
- 단점/감수한 점: 콜 깊이가 64로 고정된다.
