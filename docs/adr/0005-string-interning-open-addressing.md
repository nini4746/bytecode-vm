# 0005. 문자열 인터닝과 오픈 어드레싱 해시 테이블

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
전역 변수, 인스턴스 필드, 메서드 조회가 모두 문자열 키 해시 테이블을 쓴다. 문자열 동등 비교가 자주 일어난다.

## 결정
- 모든 문자열을 `vm.strings`에 인터닝한다.
- 해시 테이블(`table.c`)은 오픈 어드레싱, 선형 탐사, 툼스톤 삭제를 쓰고 적재율 0.75(`TABLE_MAX_LOAD`)를 넘으면 늘린다.

## 대안
- 문자열 내용 비교: `==`와 테이블 키 비교가 포인터 비교가 되지 않는다.
- 체이닝: 연속 메모리 쪽이 캐시 친화적이다.

## 결과
- 장점: `==`와 키 비교가 포인터 비교다. 툼스톤으로 삭제 후에도 탐사 체인이 유지된다.
- 단점/감수한 점: 인터닝 테이블이 GC에서 문자열을 붙잡지 않도록 약한 참조로 다뤄야 한다(0006).
