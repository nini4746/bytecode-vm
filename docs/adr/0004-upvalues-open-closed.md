# 0004. 클로저: open/closed upvalue와 주소순 정렬 리스트

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
Lox 의미론은 값이 아닌 변수 캡처다. 같은 변수를 캡처한 클로저끼리 대입이 보여야 한다.

## 결정
- upvalue는 변수가 스택에 있는 동안 스택 슬롯을 가리키고(open), 스코프를 벗어날 때 힙으로 옮긴다(closed).
- VM은 열린 upvalue를 스택 주소순 정렬 리스트(`openUpvalues`)로 관리해 같은 슬롯의 upvalue를 하나만 둔다.
- `super`는 합성 지역 변수로 선언해 같은 upvalue 장치로 캡처한다.

## 대안
- 클로저 생성 시 값 복사: 변수 캡처 의미론과 다르다.
- 매번 새 upvalue 생성: 같은 슬롯의 upvalue가 여러 개가 되어 공유 대입이 보이지 않는다.
- 클래스 객체에 슈퍼클래스 포인터: 기존 upvalue 장치를 재사용하는 쪽을 택했다.

## 결과
- 장점: 공유 대입이 보인다. close할 때 리스트 앞부분만 훑으면 된다. `super`는 클래스 선언 스코프의 정확한 슈퍼클래스를 가리킨다.
- 단점/감수한 점: upvalue를 만들 때 정렬 리스트를 탐색한다.
